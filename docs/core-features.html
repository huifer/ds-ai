Discord ↔ Pi Agent 桥接

⚡ 流式对话

Discord 消息实时转发给 Pi，支持打字机式输出，text_delta 事件实时拼装，message_end 时整段推送。

🎯 单入口设计

所有对话从 #主入口 发起，自动分类沉淀到对应频道，无需用户手动选择。

🚀 零延迟启动

~200ms 启动，无 TUI/tmux 开销。RPC 模式天然 reload-safe，零 ctx stale 错误。

🔄 稳定可靠

RPC 模式设计就是 reload-safe，不需要 5 次重试退避，彻底告别 ctx stale 问题。

核心实现

const pi = new RpcClient({
  cliPath: '/path/to/pi/cli.js',
  cwd: ROOT,
  provider: 'minimax-cn',
  model: 'MiniMax-M3',
  env: { DISCORD_TOKEN, CH_ENTRY, CH_MEMORY, ... },
  args: [
    '--mode', 'rpc',
    '--extension', toolsPath,
    '--session-dir', sessionsDir,
  ],
});

// 事件流: message_update.text_delta → message_end 整段转发
pi.onEvent(ev => {
  if (ev.type === 'message_update' && ev.assistantMessageEvent?.type === 'text_delta') {
    buf += ev.assistantMessageEvent.delta;
  }
  if (ev.type === 'message_end') {
    discord.send(channelId, text, originalUserMsg);
  }
});
架构优势对比：v2 RPC 模式 vs v1 TUI+tmux
• 启动延迟: ~10s → ~200ms
• ctx stale 错误: 有 → 无
• 5 次重试退避: 需要 → 不需要
• 流式输出: 无 → 天然支持

核心组件

MongoDB 存储 + 向量索引，支持语义搜索。

🔍 memory-context

RAG 检索上下文注入。

🧹 memory-governance

每周清理过期/归档低置信度记忆。

⭐ memory-quality

置信度更新 + 质量报告。
