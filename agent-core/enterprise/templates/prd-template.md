# 2. 一句话项目定义

> 客户是谁，他们要解决什么具体问题，我们怎么解决。

```text
ACME 公司（一家跨境电商）的客服团队希望把常见 30% 问题交给内部 AI 助手自动回答。本项目交付一个飞书 AI 客服 Agent，对接订单系统、FAQ 和人工坐席。
```

---

# 3. 背景与目标

## 3.1 业务背景

- 行业：跨境电商
- 公司规模：约 80 人
- 业务痛点：客服团队夜班人力不足，常用问题重复率高
- 现状系统：飞书、Zendesk、订单系统 API

## 3.2 目标

- **业务目标**：夜班人工介入率从 60% 降至 30%
- **产品目标**：交付一个可生产运行的飞书 AI 客服 Agent
- **度量**：6 周内上线，MTTR < 30s，机器人解决率 ≥ 50%

## 3.3 非目标

- 不替代人工坐席的最终决策
- 不做跨语言客服
- 不做主动营销

---

# 4. 用户与场景

## 4.1 用户画像

| 角色 | 画像 | 关注点 |
|---|---|---|
| 夜班客服 | 应届生，1-2 年经验 | 减少重复回答，专注复杂问题 |
| 客户 | 终端消费者 | 24/7 响应，准确转人工 |
| 客服主管 | 5 年以上经验 | 报表与质量 |

## 4.2 关键场景

1. 客户在飞书问“我的订单怎么还没到”→ Agent 查询订单 API → 给出物流状态。
2. 客户问“能不能退换”→ Agent 调 FAQ → 给出政策 → 必要时转人工。
3. 客户问“系统怎么用”→ Agent 调 Admin FAQ → 给出步骤。

## 4.3 反场景

- 客户要求立即转人工；
- 客户索取订单金额详细折扣计算；
- 客户涉及投诉升级。

# 7. 数据与集成

| 来源 | 类型 | 用途 |
|---|---|---|
| 订单系统 API | REST | 查询物流 |
| FAQ 文档 | Markdown 索引 | 知识检索 |
| 飞书开放平台 | Open API | 消息收发 |
| 管理员后台 | 内部 | 配置与监控 |

## 7.1 集成方式

- 订单 API：OAuth2.0，速率限制 60 rps；
- FAQ：每 24 小时从 Notion 同步；
- 飞书：使用 Webhook + 长连接；
- 后台：飞书多维表格 + 自有 Admin。

## 7.2 数据隔离

- 单租户部署；
- 客户订单数据不外发到任何模型 Provider；
- LLM 调用脱敏客户标识（手机号、邮箱、地址）。
